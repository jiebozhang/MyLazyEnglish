# ECDICT Dictionary Package

The app uses the separately versioned, read-only SQLite dictionary generated by `tools/import_ecdict.py`. It is not part of the Family Room database or its migration sequence. The generated database and the original CSV are intentionally excluded from Git; keep both outside the checkout and distribute only through an approved controlled data release.

## Rebuild

The importer pins ECDICT commit `bc015ed2e24a7abef49fc6dbbb7fe32c1dadaf8b` and verifies the expected source SHA-256 before producing output. PowerShell example:

```powershell
$csv = Join-Path $env:TEMP 'ecdict.csv'
$db = Join-Path $env:TEMP 'ecdictionary.sqlite'
Invoke-WebRequest -Uri 'https://raw.githubusercontent.com/skywind3000/ECDICT/bc015ed2e24a7abef49fc6dbbb7fe32c1dadaf8b/ecdict.csv' -OutFile $csv
python tools/import_ecdict.py --csv $csv --database $db
```

For a small importer fixture only, `--allow-unpinned-hash` skips source hash enforcement. Do not use that option for a release data package. Blank headwords are skipped; duplicate case-insensitive headwords are replaced by the last row in source order; malformed optional integer frequency values become SQL `NULL` and are counted. Import output reports source rows, unique entries, blank rows, duplicate replacements, invalid numeric fields, byte sizes and the verified source hash.

## Package Format and Updates

Schema version is `1` (`PRAGMA user_version=1`); dataset version is the pinned source commit. `dictionary_metadata` stores schema version, source commit, source SHA-256 and declared license. `dictionary.word` is a `COLLATE NOCASE` primary key in a `WITHOUT ROWID` table, providing the exact-word lookup index. The database reader opens it read-only and rejects unknown schema versions. No CEFR estimate is derived here; the domain result leaves CEFR and frequency source unset.

Do not fetch data at runtime. Review upstream manually on a quarterly cadence, pin a reviewed commit and hash, regenerate into a separate versioned package, validate it before replacing the installed version, and retain the prior package until validation succeeds. ECDICT does not publish a reliable update cadence.

## Device Benchmark

The repeatable Android instrumentation benchmark is `EcdictLookupBenchmarkTest`. To run it, temporarily place the generated database at `apps/android/app/src/androidTest/assets/ecdictionary.sqlite`, build `:app:assembleDebugAndroidTest`, install both APKs, then invoke `am instrument` with `-e ecdict.benchmark true` and the test class. Apply the repository's documented MIUI AppOps and foreground activation procedure after test APK installation. The test reports P50/P95 in instrumentation status. Remove the temporary asset after measurement; it is intentionally not tracked. Without the opt-in argument the test is skipped, so routine instrumentation runs do not require shipping dictionary data.
